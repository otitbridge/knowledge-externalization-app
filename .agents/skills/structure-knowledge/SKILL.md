# 知識の構造化

プロジェクトのAGENTS.mdと [知識の書式](../../../docs/knowledge-format.md) を読み、[正本テンプレート](../../../templates/canonical.md) を使う。編集者として資料に明示された内容を整理し、分野の知識を追加しない。

1. 対象資料、一次資料索引、既存正本、確認票、導入設定を確認する。原本にSRC-IDがなければ、[索引テンプレート](../../../templates/source-index.md)で原本の位置へ対応付ける。原本は書き換えない。
2. 発言・記載から、知識、観察、用語、処理、判断、理由、条件、例外を識別する。資料にない項目を埋めず、一般論へ強めない。
3. 根拠のある知識項目に固定IDと全SRC-IDを付ける。既存IDは保持し、別の意味へ使い回さない。資料に根拠がなければ正本項目にせずQとする。
4. 実行順と参照関係を区別し、明示された関係だけにR-ID・根拠・状態を付ける。記載順から実行順を推定しない。不明な接続・反対条件・終了条件はQへ記録する。
5. 新規・変更項目と関係はdraftまたはneeds-expert-reviewとする。変更に依存する範囲も確認する。明示的レビュー記録がある場合はreview-knowledgeの手順で別途反映する。
6. 文書版・根拠索引・確認票を同期し、[検証チェックリスト](../../../docs/validation-checklist.md)を実施する。既存派生物に影響すれば対象を特定し、正本から更新する。

不明点が一部にあっても、その部分を明示して根拠のある構造化を進める。曖昧な量を数値化せず、資料間の矛盾をAIの判断で解消しない。実践者の仮説を専門家の標準知識として登録しない。

完了時は、変更ID、根拠、追加Q、派生物への影響、検査結果を報告する。業務上の承認を受けたとは報告しない。
