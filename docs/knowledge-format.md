# 知識と根拠の書式

## ファイルとID

UTF-8のMarkdownを使用します。書式を拡張するときは、テンプレート・Skills・検証手順も更新します。

| 接頭辞 | 用途 |
|---|---|
| `KB-` | 正本文書 |
| `SRC-` | 原本の発言・観察・記載箇所 |
| `K-` | 種別に依存しない知識項目 |
| `R-` | 項目間の遷移・関係 |
| `Q-` | 未確定事項・確認事項 |
| `REV-` | 専門家確認・利用承認の記録 |
| `ART-` | 派生物の管理記録 |
| `WS-` | 実践記録 |
| `DEMO-` | 架空例の追加接頭辞（例：`DEMO-K-001`、`DEMO-SRC-001`） |

新規プロジェクトでは各接頭辞に連番を付け、プロジェクト全体で一意にします。既存プロジェクトへの導入では既存IDを保持します。ファイル間で番号を使い回しません。欠番を埋める目的で採番し直しません。

## 一次資料索引

SRC-IDごとに原本パス・位置・発言者または作成者・資料種別・原本を保存した完全なGitコミット・SHA-256を保持します。同じ原本の複数SRCは同じ版情報を参照できます。原本全体を指す場合も「全文」と明記します。

Markdownは見出しや行範囲、PDFはページと段落、音声は時間範囲で位置を指定します。固定版内で該当箇所を一意に見つけられることが基準です。AIによる要約を原発言として扱いません。

SHA-256は原本ファイルの**生バイト**に対して計算します。文字コード・改行・BOMを正規化しません。原本のハッシュはGitから取り出した対象版とも照合します。元プロジェクトのUTF-8/LF正規化ハッシュとは方式が異なります。

PowerShellでは `Get-FileHash -Algorithm SHA256 -LiteralPath <原本パス>` で計算できます。Git保存前後で原本のバイトが変わらないよう、付属 `.gitattributes` では `source/records/**` を `-text` としています。

## 正本文書

必須情報は文書ID、文書版、状態、対象範囲、根拠SRC-ID、一次資料索引、確認票です。対象範囲に専門的な適用条件を書く場合は、その根拠も記録します。編集上の整理範囲と、業務としての適用範囲を混同しません。

各項目は `## K-連番: 表示名` とし、種別、根拠、レビュー状態、内容を持ちます。根拠が複数なら全件を列挙します。状態に応じたレビュー記録と、関連する未解決Qを参照します。

| 種別 | 内容 |
|---|---|
| `knowledge` | 説明・判断基準・注意点などの知識 |
| `observation` | 観察の着眼点や、適用範囲を限定した観察内容 |
| `term` | 用語の定義 |
| `start` / `process` / `decision` / `end` | 明示された手順の開始・処理・判断・終端 |

種別は編集上の分類であり、正確さ・一般性・承認を保証しません。単発の観察を一般則へ書き換えません。理由・閾値・単位などを必須欄にして推測を促さず、資料にある場合だけ記載します。

## 遷移・関係

関係表は `ID / 関係 / 起点 / 条件 / 終点 / 根拠 / レビュー状態 / 確認事項 / レビュー記録` を持ちます。条件に `|` が含まれる場合はMarkdown上で `\|` と表記し、比較時は元の文字として扱います。

- `transition`：実行順・分岐。一次資料に明示されたものだけ。
- `reference`：説明上の参照関係。実行順には使わない。
- 条件がないと明示された順序だけ空欄を使う。条件不明はQとし、遷移を作らない。
- 起点・終点は同じ文書に定義されたIDとする。文書間参照は相手の文書ID・版・項目IDを本文で特定し、未確認の遷移を作らない。
- 関係がない知識文書は関係表が空でもよい。「終了」や「なし」という業務判断を意味しない。
- 廃止IDは廃止理由・置換先・根拠を履歴に残す。レビュー状態に独自の5つ目の値を追加しない。

## Mermaid・一覧・教材

正本 `canonical/<名前>.md` に対応するフローは `diagrams/<名前>-flowchart.mmd` と `diagrams/<名前>-flowchart.md` に置きます。既定は `flowchart TD` です。

ノードIDは正本IDのハイフンだけを除きます。ラベルに元IDと正本の表示名を含めます。`start/end` は終端形、`decision` はひし形、その他は矩形です。`transition` のみをフロー矢印にします。矢印の条件は正本と完全一致させ、条件不明を「はい」などに置き換えません。

Mermaid構文のための文字エスケープは可能ですが、表示上の意味と文言は変えません。未レビュー項目・関係の状態を凡例と対応表に示します。色だけに依存しません。表示用Markdownには同一のMermaid本文を埋め込みます。

手順のない知識はID・内容・根拠・状態の一覧にできます。図の体裁のために接続を追加しません。部分図では対象IDと省略範囲を管理票に記録し、経路をつなぎ替えません。承認済み項目だけを抽出して途中の未承認経路を飛び越すことも禁止します。

教材の説明・正答・フィードバックは正本IDへ対応付けます。言い換え・設問化は意味を増やさない範囲に限定します。誤答選択肢や架空の条件・数値を必要とする場合は、今回の根拠からは作成できないことを示し、記述式などを選びます。架空教材を求められた場合は別のDEMO成果物として扱います。

## 版の特定

原本は `原本Gitコミット + パス + SRC-ID + SHA-256`、正本は `文書ID + 文書版 + Gitコミット + パス` で特定します。生成中の未コミット正本は基準コミット・未コミットの表示・入力SHA-256で識別し、承認済み版と同一視しません。

レビュー記録は確認した正本の本文・関係を特定する版とSHA-256を残します。確認後、状態・レビュー記録への参照だけを更新するときは、その変更を明記します。知識本文や接続まで変えた場合には新たな確認が必要です。
