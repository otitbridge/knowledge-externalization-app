# 検証チェックリスト

このスターターの検証は、下記の照合と記録を人またはAIが実施する方式です。自動検証器は未実装です。検査対象がない項目は「対象なし」、環境不足などで行えない項目は「未実施」と区別します。

## 一次資料と正本

- 原本を上書き・削除していないか。訂正が別資料と新規SRC-IDになっているか。
- 各SRCの原本・指定位置が実在するか。固定コミットを取得でき、原本SHA-256と一致するか。
- 文書ID・項目ID・関係IDが一意で、既存IDが消えたり再利用されたりしていないか。
- 全項目・関係に種別、実在する根拠、許可されたレビュー状態があるか。
- 根拠を実際に読み、断定の強さ、適用範囲、数値、単位、因果関係が増えていないか。
- 起点・終点・Q・レビュー記録への参照が解決するか。関係の根拠が接続そのものを説明しているか。
- 実践者の仮説や単発の観察が、専門家レビューなしに標準知識へ昇格していないか。

## 確認票とレビュー

- 未確定・矛盾・未確認の反対条件がQに記録されているか。
- Qの現行質問と回答履歴が区別され、closedの理由と反映先があるか。
- 状態昇格に、対象版・ID・確認者・役割・日付・明示的な判断があるか。
- 変更箇所と依存する接続の再レビューが必要か。旧版の承認を流用していないか。
- 正式利用に影響する未解決Qが承認範囲に残っていないか。

## 派生物

- 入力正本の文書ID・版・コミットまたは未コミット表示・ハッシュが記録されているか。
- 対象ID集合が正本の生成対象範囲と一致するか。部分出力は範囲と省略内容が明示されているか。
- 正本と図で、ノードID、表示名、形状、遷移先、条件が一致するか。
- Mermaidの生ファイルと表示用Markdown内のコードが一致するか。
- Mermaidを表示できる環境で構文・表示を確認したか。表示していないなら、その検査を未実施と記録したか。
- 図・教材に未レビュー状態と用途が表示され、DEMOが混在していないか。
- 教材の説明・正答・フィードバックが正本IDへ対応し、専門知識の追加がないか。

## 差分と記録

Git管理後は `git diff --check`、`git diff --stat`、`git diff`、`git status --short` で変更範囲を確認します。新規未追跡ファイルはdiffに出ないため、本文も確認します。

自動検証器を導入した場合は、そのコマンド・結果・対象版を記録します。パーサー変更時は正常例に加え、欠落根拠・重複ID・未定義遷移・不正な状態・DEMO混在・版ずれを拒否するテストを実施します。

[検証記録テンプレート](../templates/validation-report.md)に結果を残し、正本と派生物の変更をまとめて保存します。構造整合の成功と、専門家確認・業務利用の承認を区別して報告してください。
